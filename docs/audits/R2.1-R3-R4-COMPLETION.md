# R2.1, R3, and R4 completion record

## R2.1 generic editor integration

The EmVB admin/editor no longer imports `@perkyzz/emvb-daisyui`. Add-panel components and recipes are enumerated from `componentProviders()`. Element creation resolves `provider:<provider-id>:<component-id>`. Settings resolve descriptors by registered provider and node type. Recipe insertion uses provider recipe and validation contracts. Legacy `daisy:<id>` insertion IDs remain accepted during migration. `packages/emvb/package.json` no longer depends on daisyUI.

## R3 schema 18 generic provider nodes

Layout schema 18 replaces persisted `type: "daisy"` with `type: "provider"`, adding `provider`, `component`, optional `providerVersion`, semantic `props`, optional `providerMeta`, and children. Migration 17→18 recursively converts daisyUI nodes, moves `props.theme` to `providerMeta.theme`, and retains IDs, children, and shared fields. Core rendering resolves the provider registry and safely falls back when a provider is unavailable.

## R4 official CSS conformance gate

The exact daisyUI 5.7.50 and Tailwind CSS 4.1.17 boundary remains pinned. `verifyCompiledCss()` checks required selectors in CSS produced by the real official build. The CLI accepts a compiled CSS file and fails CI when selectors are missing. Local unit tests validate the verifier; release CI must invoke it against the output of the pinned Tailwind+daisyUI compilation.
